# 搜打撤关卡内 Demo 模块化开发阶段

## 1. 目标

本计划以“完成一个可试玩的关卡内 Demo”为唯一目标。Demo 不追求完整产品化，只验证一局内的核心体验：

- 搜索资源。
- 战斗承压。
- 背包取舍。
- 残页保底撤离。
- 死亡清零。
- 肉鸽三选一换收益。
- 撤离点 30 秒挑战。

推荐基于 `search-strike-extract` 这类已有搜打撤原型推进。第一原则是先复用现有搜索、战斗、撤离、结算结构，再逐步替换成目标规则。

## 2. 总体阶段

| 阶段 | 模块目标 | 完成后状态 |
|---|---|---|
| Phase 0 | 项目跑通与代码摸底 | 能运行原型，并知道核心逻辑在哪里改。 |
| Phase 1 | 单局基础流程 | 玩家能进入关卡、移动、战斗、死亡、结束。 |
| Phase 2 | 搜索与掉落 | 玩家能搜索资源点并获得局内收益。 |
| Phase 3 | 背包与收益容器 | 收益进入临时背包，背包容量产生取舍。 |
| Phase 4 | 撤离残页与普通撤离 | 残页决定能否保底撤离。 |
| Phase 5 | 怪物刷新与压力曲线 | 怪物持续刷新，并随时间变强。 |
| Phase 6 | 肉鸽三选一 | 玩家主动承担诅咒换收益倍率。 |
| Phase 7 | 撤离点 30 秒挑战 | 玩家可挑战完美撤离。 |
| Phase 8 | HUD、结算与调试 | 玩家能看懂状态，团队能调试验证。 |
| Phase 9 | 试玩调参与验收 | Demo 可连续试玩并判断玩法是否成立。 |

## 3. Phase 0：项目跑通与代码摸底

### 目标

确认选定原型能本地运行，并整理出可复用模块和需要新增模块。

### 输入

- 已选开源项目。
- 本地运行环境。

### 开发任务

| 任务 | 说明 |
|---|---|
| 跑通项目 | 本地启动，确认能正常进入游戏。 |
| 玩 3 局原型 | 记录已有的搜索、战斗、撤离、死亡损失、结算流程。 |
| 标记核心文件 | 找到玩家、敌人、掉落、背包、撤离点、结算、HUD 相关代码。 |
| 画出当前流程 | 整理原项目当前单局状态流。 |
| 整理改造表 | 列出“保留 / 修改 / 新增 / 删除”的功能点。 |

### 产出物

- `docs/code-map.md`：核心代码位置说明。
- `docs/adaptation-notes.md`：原型改造清单。

### 完成标准

- 可以稳定运行原项目。
- 明确撤离逻辑在哪里。
- 明确死亡损失逻辑在哪里。
- 明确搜索容器和掉落逻辑在哪里。
- 明确 HUD 和结算页面在哪里。

## 4. Phase 1：单局基础流程模块

### 目标

建立 Demo 的单局生命周期，让项目从“原游戏”变成“关卡内 Demo 框架”。

### 模块边界

负责：

- 开始一局。
- 初始化玩家、地图、资源点、刷怪点。
- 监听玩家死亡。
- 进入结算。

不负责：

- 复杂掉落。
- 背包规则。
- 三选一。
- 完美撤离。

### 开发任务

| 任务 | 说明 |
|---|---|
| 定义单局状态 | `Init`、`Playing`、`Dead`、`Extracting`、`Challenge`、`Settled`。 |
| 初始化关卡 | 重置玩家、敌人、资源点、掉落、计时器。 |
| 死亡监听 | 玩家血量归零后进入死亡处理。 |
| 基础结算入口 | 先只弹出成功/失败结果，不接正式奖励。 |
| 重开流程 | 结算后可以重新开始一局。 |

### 关键数据

```json
{
  "runState": "Playing",
  "elapsedTime": 0,
  "isSettled": false,
  "deathCount": 0
}
```

### 完成标准

- 玩家可以开始一局。
- 玩家死亡后能进入失败结果。
- 结算后可以重新开始。
- 单局数据不会污染下一局。

## 5. Phase 2：搜索与掉落模块

### 目标

建立“搜”的基础体验：玩家靠近资源点，消耗时间或交互动作，获得局内掉落。

### 模块边界

负责：

- 资源点交互。
- 掉落生成。
- 掉落拾取。

不负责：

- 背包满处理。
- 正式收益入库。
- 撤离规则。

### 开发任务

| 任务 | 说明 |
|---|---|
| 资源点类型 | 至少实现普通宝箱、矿堆、高价值宝箱 3 类。 |
| 交互方式 | 靠近后点击或停留 1 - 2 秒完成搜索。 |
| 资源点状态 | 未搜索、搜索中、已搜索。 |
| 掉落类型 | 局内货币、残页、可带出物、临时增益。 |
| 掉落表现 | 允许直接进入背包，也可生成地面拾取物。 |

### 关键数据

```json
{
  "interactId": "chest_001",
  "type": "normal_chest",
  "searchTime": 1.5,
  "dropTableId": "drop_chest_normal",
  "isSearched": false
}
```

### 完成标准

- 地图内至少有 5 个可搜索资源点。
- 每个资源点只能被搜索一次。
- 玩家能从资源点获得不同类型掉落。
- 高价值资源点明显比普通资源点更值得去。

## 6. Phase 3：局内背包与收益模块

### 目标

让玩家获得的收益进入临时背包，并通过容量限制制造取舍。

### 模块边界

负责：

- 局内背包容量。
- 可带出物品记录。
- 当前收益估值。
- 背包满处理。

不负责：

- 正式账号背包。
- 复杂二维格子摆放。
- 商业化扩容。

### 开发任务

| 任务 | 说明 |
|---|---|
| 简化容量 | 第一版用数字容量，例如 `12`。 |
| 物品占格 | 普通碎片 1 格，高级碎片 2 格，完整宝物 3 格。 |
| 拾取判断 | 容量足够则进入背包，不足则阻止拾取。 |
| 背包满提示 | 显示“背包已满”。可先不做复杂替换。 |
| 收益估值 | 根据物品基础价值计算当前可带出收益。 |

### 关键数据

```json
{
  "capacity": 12,
  "used": 7,
  "estimatedValue": 1280,
  "items": [
    {"id": "treasure_fragment_low", "slotCost": 1, "value": 100},
    {"id": "treasure_complete", "slotCost": 3, "value": 800}
  ]
}
```

### 完成标准

- 背包容量能被填满。
- 背包满后玩家不能无成本继续拿收益。
- HUD 能显示容量和收益估值。
- 结算页能展示背包内收益。

## 7. Phase 4：撤离残页与普通撤离模块

### 目标

建立保底撤离规则：玩家收集足够撤离卷轴残页后，可以提前普通撤离；残页不足死亡则清零。

### 模块边界

负责：

- 残页计数。
- 普通撤离条件。
- 死亡结算分支。
- 普通撤离结算。

不负责：

- 30 秒完美撤离挑战。
- 多关卡解锁。

### 开发任务

| 任务 | 说明 |
|---|---|
| 残页掉落 | 资源点和怪物都有概率掉落残页。 |
| 残页计数 | 显示 `0 / 4` 到 `4 / 4`。 |
| 普通撤离按钮 | 残页满后允许手动撤离。 |
| 死亡分支 | 残页不足死亡：失败清零；残页足够死亡：普通撤离。 |
| 结算类型 | 增加 `Failed`、`NormalExtract` 两种结果。 |

### 关键数据

```json
{
  "scrollFragments": 3,
  "requiredFragments": 4,
  "canNormalExtract": false
}
```

### 完成标准

- 残页不足死亡，本局背包收益清零。
- 残页达到 4 后，玩家能提前撤离。
- 残页达到 4 后死亡，按普通撤离带出收益。
- 玩家能明确知道还差几个残页。

## 8. Phase 5：怪物刷新与压力曲线模块

### 目标

建立“越拖越危险”的局内压力，让玩家产生撤离决策。

### 模块边界

负责：

- 定时刷怪。
- 怪物等级成长。
- 狂暴状态。
- 精英触发。

不负责：

- 完整 Boss 技能。
- 大量怪物种类。
- 高精度数值平衡。

### 开发任务

| 任务 | 说明 |
|---|---|
| 固定刷怪点 | 地图内放置 3 - 5 个刷怪点。 |
| 定时刷新 | 每隔固定时间刷普通怪。 |
| 怪物等级 | 每 45 秒提升 1 级。 |
| 数值倍率 | 生命、攻击、速度或刷新频率按等级提高。 |
| 狂暴状态 | 5 分钟后进入狂暴，刷新更快、攻击更高。 |
| 精英触发 | 开启高价值宝箱或进入精英房时刷新精英。 |

### 关键数据

```json
{
  "monsterLevel": 3,
  "levelInterval": 45,
  "enrageTime": 300,
  "hpMultiplier": 1.45,
  "attackMultiplier": 1.3,
  "spawnIntervalMultiplier": 0.85
}
```

### 完成标准

- 玩家能感知 3 分钟后怪物明显变强。
- 5 分钟后进入狂暴状态。
- 狂暴有明确提示。
- 玩家如果一直贪资源，会明显更容易死亡。

## 9. Phase 6：肉鸽三选一模块

### 目标

加入主动风险选择：玩家通过选择诅咒获得收益倍率，提高单局策略性。

### 模块边界

负责：

- 三选一触发。
- 选项生成。
- 正负效果应用。
- 收益倍率累计。

不负责：

- 大量复杂技能。
- 长期构筑。
- 职业专属词条。

### 开发任务

| 任务 | 说明 |
|---|---|
| 触发条件 | 击杀数、搜索次数或时间达到阈值。 |
| 选项池 | 第一版做 6 个选项。 |
| 选择 UI | 展示“获得 / 代价 / 收益提升”。 |
| 效果应用 | 至少支持玩家伤害、移速、背包容量、掉落、刷怪频率。 |
| 倍率记录 | 当前收益倍率显示在 HUD，并影响结算。 |

### 首批选项

| 名称 | 获得 | 代价 | 收益 |
|---|---|---|---:|
| 贪婪之手 | 采集速度 +30% | 刷怪间隔 -15% | +15% |
| 血税契约 | 残页掉率 +20% | 治疗效果 -20% | +25% |
| 重压行军 | 背包容量 +2 | 移速 -8% | +20% |
| 狂潮引路 | 高价值掉落 +20% | 魔物升级间隔 -10 秒 | +35% |
| 玻璃锋刃 | 玩家伤害 +20% | 受到伤害 +15% | +20% |
| 精英献祭 | 精英掉落 +30% | 精英出现率 +30% | +30% |

### 关键数据

```json
{
  "selectedCurses": ["greedy_hand", "glass_blade"],
  "rewardMultiplier": 1.38,
  "triggerCount": 2,
  "maxTriggerCount": 2
}
```

### 完成标准

- 单局能触发 1 - 2 次三选一。
- 每个选项都同时有收益和代价。
- 选择后能在局内或结算中感知效果。
- 结算收益会受倍率影响。

## 10. Phase 7：撤离点 30 秒挑战模块

### 目标

建立完美撤离目标：玩家到达撤离点后，主动触发 30 秒生存验证，成功后获得更高收益。

### 模块边界

负责：

- 撤离点激活。
- 30 秒倒计时。
- 挑战期间刷怪。
- 完美撤离结算。

不负责：

- 多关卡推进。
- 正式通关奖励发放。
- 复杂 Boss 房。

### 开发任务

| 任务 | 说明 |
|---|---|
| 撤离点区域 | 玩家进入区域后显示可交互提示。 |
| 激活条件 | 玩家点击或停留后开始挑战。 |
| 倒计时 | 固定 30 秒。 |
| 挑战刷怪 | 倒计时期间持续刷怪或刷精英。 |
| 成功条件 | 倒计时结束时玩家仍存活。 |
| 失败处理 | 按当前残页状态进入失败或普通撤离。 |
| 完美收益 | 完美撤离收益倍率高于普通撤离。 |

### 关键数据

```json
{
  "challengeDuration": 30,
  "remainingTime": 18.5,
  "isChallengeActive": true,
  "perfectExtractMultiplier": 1.5
}
```

### 完成标准

- 玩家能主动触发撤离点挑战。
- 挑战期间有明显倒计时。
- 挑战成功进入完美撤离结算。
- 挑战失败不会出现规则歧义。

## 11. Phase 8：HUD、结算与调试模块

### 目标

让玩家看懂目标，让开发和策划能快速验证各分支。

### HUD 必须展示

- 单局时间。
- 魔物等级。
- 狂暴状态。
- 残页进度。
- 背包容量。
- 当前收益估值。
- 当前收益倍率。
- 当前撤离状态。
- 撤离挑战倒计时。

### 结算页必须展示

| 字段 | 说明 |
|---|---|
| 撤离类型 | 失败、普通撤离、完美撤离。 |
| 背包收益 | 本局可带出物品价值。 |
| 收益倍率 | 三选一和完美撤离倍率。 |
| 最终收益 | Demo 内计算结果即可。 |
| 失败原因 | 残页不足死亡、挑战失败等。 |

### 调试按钮

- 增加残页。
- 清空残页。
- 填满背包。
- 触发三选一。
- 提升魔物等级。
- 进入狂暴。
- 传送撤离点。
- 强制普通撤离。
- 强制完美撤离。
- 强制死亡。

### 完成标准

- 玩家无需看说明也能理解当前目标。
- 三种结算都能通过调试按钮快速触发。
- 策划能在 1 分钟内验证任意核心分支。

## 12. Phase 9：试玩调参与 Demo 验收

### 目标

通过多局试玩判断 Demo 是否达到“可以继续投入”的标准。

### 试玩方法

- 至少连续试玩 10 局。
- 每局记录撤离类型、单局时长、死亡时间、背包价值、残页数量、三选一选择。
- 至少让 2 个非开发人员试玩。

### 核心指标

| 指标 | 目标 |
|---|---|
| 平均单局时长 | 5 - 8 分钟。 |
| 普通撤离达成时间 | 3 - 5 分钟。 |
| 完美撤离达成时间 | 5 - 8 分钟。 |
| 失败撤离率 | 15% - 30%。 |
| 背包满触发 | 试玩中至少出现一次。 |
| 三选一触发 | 单局 1 - 2 次。 |
| 玩家理解目标 | 1 分钟内知道要搜资源、凑残页、找撤离点。 |

### 完成标准

- Demo 可以连续跑 3 局无流程阻塞。
- 失败、普通撤离、完美撤离都能稳定触发。
- 玩家会出现“继续搜还是撤”的选择。
- 玩家能理解三选一是风险换收益。
- 团队能基于试玩结果决定是否继续做正式版本。

## 13. 模块依赖顺序

```text
Phase 0 项目跑通
  -> Phase 1 单局基础流程
    -> Phase 2 搜索与掉落
      -> Phase 3 背包与收益
        -> Phase 4 残页与普通撤离
          -> Phase 5 怪物压力曲线
            -> Phase 6 肉鸽三选一
              -> Phase 7 撤离点挑战
                -> Phase 8 HUD/结算/调试
                  -> Phase 9 试玩验收
```

允许并行的内容：

- HUD 可以从 Phase 2 开始同步做简版。
- 怪物压力曲线可以和搜索掉落并行。
- 三选一 UI 可以先用临时弹窗。
- 调试按钮应尽早做，不要等最后。

## 15. 砍需求原则

如果时间不足，按以下顺序砍：

1. 砍正式美术，只保留占位。
2. 砍复杂背包，只保留数字容量。
3. 砍 Boss，只保留精英怪或强化怪潮。
4. 砍条件传送门和祭坛。
5. 砍复杂掉落表，只保留固定掉落和简单权重。
6. 砍部分三选一词条，但至少保留 3 个。

不能砍：

- 死亡清零。
- 残页普通撤离。
- 撤离点挑战。
- 怪物随时间变强。
- 至少一次风险收益选择。

这些是搜打撤关卡内 Demo 是否成立的核心判断依据。
