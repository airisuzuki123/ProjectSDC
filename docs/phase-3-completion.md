# Phase 3 完成记录：简化背包与收益容器

## 1. 阶段目标

Phase 3 的目标是让局内收益进入一个有限容量的临时背包，并通过不同物品占格制造“继续搜还是撤”的取舍。

本阶段不做复杂二维格子摆放，只做数字容量：

```text
已用格数 / 总格数
```

| 能力 | 状态 |
|---|---|

## 3. 代码改动

### `js/data.js`

改动：

- `BACKPACK_SLOTS` 从 `24` 调整为 `12`。
- 给可带出物增加 `slotCost`。

示例：

```js
{ id: 'v_cash', slotCost: 1 }
{ id: 'v_doc', slotCost: 2 }
{ id: 'v_gpu', slotCost: 3 }
{ id: 'v_bitcoin', slotCost: 3 }
```

### `js/entities.js`

新增：

```js
backpackUsed()
backpackFree()
```

并将：

```js
backpackCount()
```

改为返回当前已用格数。

`addLoot(id, n)` 现在会按剩余格数判断能否加入背包，而不是只看堆叠项数量。

### `js/ui.js`

局内背包弹窗的每个物品显示占格信息：

```text
3 格 · 点击=丢弃
```

### `js/i18n.js`

新增中英文占格文案：

- `ui.inv.slotCost`

### `tools/smoke.js`

新增测试：

```text
backpack capacity uses item slotCost, not stack entries
```

## 5. 当前体验效果

玩家在 Demo 中会更快遇到背包容量压力：

- 低价值物通常占 1 格。
- 高价值物会占更多格。
- 背包满后无法无成本继续拾取。
- 玩家需要在当前收益、残页进度、血量状态和撤离风险之间做取舍。

## 6. 下一步建议

建议进入 Phase 5：怪物刷新与压力曲线。

当前项目已有初始敌人和 AI，但还没有“随时间持续增强”的压力。下一步应实现：

- 魔物等级。
- 每 45 秒提升一次怪物强度。
- 5 分钟后狂暴。
- HUD 显示魔物等级和狂暴状态。

这会让玩家感知“越贪越危险”，配合背包容量形成撤离决策。
