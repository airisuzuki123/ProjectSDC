# 搜打撤副本 Demo 设计与技术路线

## 1. 项目定位

本 Demo 目标是验证一套适配俯视角弹幕动作战斗的“搜打撤”副本玩法：玩家消耗体力进入箱庭式地图，在持续增强的怪物压力下搜索资源、承担风险、选择是否提前撤离，最终通过撤离点的 30 秒生存验证完成关卡推进。

Demo 不追求完整商业化包装，优先验证以下问题：

- 单局 5 - 8 分钟内，搜索、战斗、背包整理、撤离决策是否形成清晰循环。
- “越贪越危险”的压力曲线是否成立。
- 撤离卷轴残页是否能提供明确的保底撤离目标。
- 肉鸽三选一是否能让局内成长和副本收益形成有效权衡。
- 30 秒撤离点挑战是否能验证续航、机动、减伤、回蓝、冷却循环等构筑能力。

## 2. 核心体验目标

| 目标 | 说明 |
|---|---|
| 控制单局时长 | 单次参与控制在 5 - 8 分钟，适合移动端碎片化体验。 |
| 保留搜打撤体验 | 保留开放地图搜索、收益携带、风险撤离、贪婪决策。 |
| 降低理解成本 | 不做复杂大地图迷宫，不做多层房间选择，玩家目标清晰。 |
| 适配弹幕动作战斗 | 强调走位、技能循环、职业 BD 差异和短时间高密度战斗。 |
| 验证续航属性 | 撤离点挑战用于验证回血、护盾、减伤、回蓝、冷却循环等能力。 |
| 提供分层体验 | 普通玩家可提前撤离，高练度玩家可挑战完美撤离获取更高收益。 |
| 支持长期运营 | 后续可接入赛季词条、主题场景、掉落轮换和构筑目标。 |

## 3. Demo 版本范围

### 3.1 必做范围

- 一个主题场景。
- 一张箱庭式线性推进地图，包含主路线和少量支路。
- 出生点、资源点、条件资源点、刷怪点、祭坛、撤离点。
- 局内背包与拾取逻辑。
- 银币、撤离卷轴残页、钥匙、宝物碎片、完整宝物。
- 怪物随时间提升等级，并在达到上限后进入狂暴状态。
- 肉鸽三选一：选择诅咒或局内效果，换取收益倍率提升。
- 普通撤离、失败撤离、完美撤离三种结算。
- 撤离点 30 秒生存挑战。
- 基础配置表驱动：地图、怪物、掉落、资源点、诅咒、撤离规则。

### 3.2 暂不做范围

- 多主题场景。
- 多人匹配或 PvP。
- 大地图迷宫和复杂路径寻路。
- 完整商业化付费系统。
- 完整赛季系统。
- 大量职业、装备、技能的正式数值平衡。
- 房间随机任务和复杂事件链。

## 4. 单局核心循环

1. 玩家消耗体力进入副本。
2. 系统生成地图、资源点、刷怪点、撤离点和局内初始配置。
3. 玩家沿主路线探索，开启资源点、击杀怪物、收集掉落。
4. 玩家获得局内货币、宝物碎片、完整宝物、撤离卷轴残页等资源。
5. 怪物随时间提升等级，地图压力持续升高。
6. 达成条件时触发肉鸽三选一，玩家选择诅咒或局内效果。
7. 玩家根据背包容量、血量状态、收益价值、残页数量决定继续搜索或撤离。
8. 收集足够撤离卷轴残页后，玩家可以提前普通撤离。
9. 到达撤离点后，玩家触发 30 秒强压力挑战。
10. 挑战成功则完美撤离并解锁下一关；挑战失败按当前规则结算。

## 5. 撤离与失败规则

| 类型 | 触发条件 | 收益结果 |
|---|---|---|
| 失败撤离 | 未收集足够撤离卷轴残页时死亡且不复活。Demo 中整局最多复活一次。 | 本局背包收益全部清零。 |
| 普通撤离 | 收集 4 张撤离卷轴残页后，手动选择中途撤离；或收集齐残页后死亡触发保底带出。 | 背包内可带出物品全额带出。 |
| 完美撤离 | 在撤离点触发 30 秒生存验证，并在倒计时结束时仍然存活。 | 带出背包收益，获得关卡通关奖励，并解锁下一关。 |

设计重点：

- 失败撤离制造风险底线。
- 普通撤离提供保底目标，避免玩家因一次失误完全失去体验动力。
- 完美撤离承担高练度验证，不做纯数值门槛，允许通过操作、续航和构筑通过。

## 6. 地图设计

### 6.1 地图原则

| 原则 | 说明 |
|---|---|
| 一眼可理解 | 玩家入场后能快速判断前进方向、沿途资源和终点撤离目标。 |
| 尽量不走回头路 | 主路线单向推进，除少量高额奖励支路外，出生点至撤离点距离固定。 |
| 搜索有收益 | 每个推进段都有可交互物资点，保证移动过程有目标。 |
| 压力逐步提高 | 越靠近后段，怪物密度、资源价值和死亡风险越高。 |
| 分支可取舍 | 支路提供高价值资源或额外残页，但需要消耗钥匙、银币、时间或战斗成本。 |

### 6.2 Demo 地图结构

推荐第一版使用“单主线 + 两个支路 + 终点撤离房”的结构：

```text
出生点
  |
资源教学段
  |
刷怪压力段 ---- 支路资源房
  |
条件传送门
  |
中段战斗房 ---- 高价值宝箱房
  |
精英怪房
  |
撤离点挑战房
```

### 6.3 基础地图元素

| 交互点 | 生成方式 | 参数 | 交互方式 | 结果 |
|---|---|---|---|---|
| 出生点 | 地图初始化生成 | 初始朝向、保护时间 | 自动触发 | 玩家入场。 |
| 条件传送门 | 固定点位生成 | 开启条件、交付时长、消耗类型 | 玩家在范围内停留并交付资源 | 开启新区域。 |
| 条件资源点 | 固定或随机点位生成 | 开启条件、领取次数区间、掉落 ID | 玩家停留交互 | 掉落资源或增益。 |
| 普通资源点 | 宝箱、矿堆、场景物件 | 领取次数、掉落 ID | 靠近后停留采集 | 获得道具、银币、残页、宝物碎片。 |
| 刷怪点 | 固定点位或房间配置生成 | 前置 CD、波次、间隔、复活间隔 | 战斗击杀 | 掉落局内资源或触发进度。 |
| 祭坛 | 固定或随机生成 | Buff 池、代价、持续时间 | 点击交互 | 回复、护盾、能量、药剂、短时增益。 |
| 撤离点 | 终点房固定生成 | 倒计时、刷怪波次、挑战强度 | 静止激活后开始挑战 | 触发普通/完美撤离事件。 |

## 7. 怪物与压力曲线

### 7.1 魔物等级

玩家进入关卡后开始计时，每隔一段时间提升魔物等级。每次提升会按照倍率增加怪物血量、攻击、移动速度或弹幕密度。

推荐 Demo 参数：

| 参数 | 建议值 | 说明 |
|---|---:|---|
| 魔物等级提升间隔 | 45 秒 | 保证玩家能明显感知压力变化。 |
| 魔物等级上限 | 6 级 | 适配 5 - 8 分钟单局。 |
| 每级生命提升 | 15% | 先保守，避免后期打不动。 |
| 每级攻击提升 | 10% | 强化风险，但不瞬间秒杀。 |
| 狂暴触发时间 | 5 分钟后 | 等级达到上限后进入狂暴。 |
| 狂暴效果 | 生命 +60%，攻击 +40%，刷新频率 +30% | 用于逼迫玩家撤离或挑战终点。 |

### 7.2 精英怪与 Boss

精英怪与 Boss 不建议完全按时间硬刷，而应由“时间 + 行为 + 区域”共同触发：

- 时间触发：进入副本 120 秒后，精英怪池开始生效。
- 搜索触发：开启高价值资源点后，有概率刷出守卫精英。
- 区域触发：进入精英怪房或撤离点挑战房时强制刷新。
- 贪婪触发：玩家累计选择高收益诅咒后，提高精英和 Boss 出现概率。

## 8. 局内背包

### 8.1 基础规则

- 玩家进入副本后获得固定大小局内背包。
- 可带出物品进入局内背包，占用格子。
- 局内货币、钥匙、撤离卷轴残页、诅咒技能不进入背包。
- 背包满后，拾取会进入待拾取状态，玩家需要手动丢弃或替换。
- 购买 BP 或后续成长系统可增加背包容量，但 Demo 只保留配置字段。

### 8.2 背包 Demo 设计

第一版推荐使用简化格子背包，而不是复杂俄罗斯方块式摆放：

- 背包容量：12 格。
- 普通宝物碎片：1 格。
- 高级宝物碎片：2 格。
- 完整宝物：3 格。
- 结算时按物品配置折算收益。

这样可以快速验证“背包容量带来的取舍”，避免第一版工程成本过高。

## 9. 掉落与收益

| 掉落类型 | 归属 | 说明 |
|---|---|---|
| 肉鸽效果/诅咒 | 局内掉落 | 玩家三选一，获得增益或负面效果，并提升副本收益倍率。 |
| 银币 | 局内货币 | 仅限副本内使用，无法带出，用于开门、开启资源点、兑换等。 |
| 撤离卷轴残页 | 局内撤离道具 | 收集 4 张后可提前普通撤离，不进入常规背包。 |
| 钥匙 | 局内功能道具 | 用于开启特殊房间或高价值资源点，不占背包格子。 |
| 贵重物 | 可带出掉落 | 可折算养成货币、时装币或赛季资源。 |
| 宝物碎片 | 可带出掉落 | 有品质区分，占据背包格子。 |
| 完整宝物 | 珍稀掉落 | 高价值目标，推动玩家承担更高风险。 |

### 9.1 收益倍率

收益倍率由以下因素共同决定：

- 关卡层数。
- 当前主题场景。
- 玩家选择的诅咒数量。
- 是否完美撤离。
- 是否开启高价值支路。

推荐公式：

```text
最终收益 = 背包物品基础价值 * 关卡倍率 * 诅咒收益倍率 * 撤离类型倍率
```

撤离类型倍率建议：

- 失败撤离：0。
- 普通撤离：1.0。
- 完美撤离：1.3 - 1.5。

## 10. 肉鸽三选一设计

原文档中“三选一”偏局内临时属性升级。建议 Demo 调整为“诅咒 + 收益提升”的组合，以更贴合搜打撤风险收益。

### 10.1 触发方式

- 每累计击杀一定数量怪物触发一次。
- 每开启一定数量资源点触发一次。
- 开启特殊祭坛触发一次。
- 进入撤离点前最多触发 3 次，避免堆叠过深。

### 10.2 选项结构

每个选项由三部分构成：

- 正面效果：提升输出、续航、机动、拾取效率或资源获取。
- 负面诅咒：提升怪物强度、降低容错、增加撤离压力。
- 收益倍率：根据负面强度提供 10% - 40% 的收益提升。

示例：

| 名称 | 正面效果 | 负面诅咒 | 收益提升 |
|---|---|---|---:|
| 贪婪之手 | 资源点采集速度 +30% | 怪物刷新间隔 -15% | +15% |
| 血税契约 | 击杀精英额外掉落残页概率 +20% | 治疗效果 -20% | +25% |
| 重压行军 | 背包容量 +2 | 移动速度 -8% | +20% |
| 狂潮引路 | 宝物掉落品质提升 | 魔物等级提升间隔 -10 秒 | +35% |

## 11. UI 与信息展示

Demo 需要优先保证信息清晰，不追求完整美术包装。

### 11.1 局外入口

- 通关指定主线或小秘境层数后解锁玩法。
- 主界面“开始冒险”区域展示两个重点入口：混沌千域、异界裂隙。
- 小秘境入口下沉为次级入口。
- 主题场景选择不展示上限，避免玩家误解为短期封顶内容。

### 11.2 局内 HUD

必要信息：

- 当前魔物等级与狂暴状态。
- 当前时间。
- 撤离卷轴残页进度，例如 `2 / 4`。
- 当前背包容量，例如 `8 / 12`。
- 当前收益估值。
- 当前诅咒数量与收益倍率。
- 小地图或方向指引。
- 撤离点距离或终点方向。

### 11.3 关键提示

- 撤离卷轴残页收集完成时，必须有强提示。
- 进入狂暴前 10 秒需要倒计时提示。
- 背包满时需要明确提示“替换 / 丢弃 / 放弃拾取”。
- 进入撤离点挑战前，需要展示 30 秒挑战规则。

## 12. 数据配置设计

### 12.1 掉落表

新增 `drop` 表，用于副本内搜取掉落。

| 字段 | 类型 | 说明 |
|---|---|---|
| id | int | 掉落 ID，支持最多一层嵌套。 |
| sup_des | string | 策划备注字段。 |
| entry_probability | float | 进入该掉落 ID 的概率。 |
| type | enum | `independent` 独立概率；`weighted` 权重掉落。 |
| drop_content | array | 掉落内容数组。 |

`drop_content` 建议结构：

```json
{
  "item_type": "item | drop | curse",
  "probability_or_weight": 1000,
  "target_id": 10101,
  "count": 1
}
```

### 12.2 关键配置表

| 配置表 | 作用 |
|---|---|
| `dungeon_scene` | 主题场景、关卡、地图资源、撤离点配置。 |
| `dungeon_room` | 房间类型、资源点、刷怪点、连接关系。 |
| `dungeon_interact` | 宝箱、矿堆、祭坛、传送门等交互物配置。 |
| `dungeon_spawn` | 怪物波次、刷新间隔、复活间隔、精英触发。 |
| `dungeon_monster_scaling` | 魔物等级提升、狂暴状态、数值倍率。 |
| `dungeon_drop` | 掉落表。 |
| `dungeon_item` | 局内道具、可带出道具、背包占格、折算价值。 |
| `dungeon_curse` | 肉鸽三选一选项、正负效果、收益倍率。 |
| `dungeon_extract` | 普通撤离、完美撤离、失败撤离规则。 |

## 13. Demo 技术路线

### 13.1 推荐技术栈

建议使用 Unity 构建 Demo，原因是该玩法依赖实时战斗、碰撞、技能表现、地图编辑和移动端适配。

| 层级 | 推荐方案 | 说明 |
|---|---|---|
| 引擎 | Unity 2022 LTS 或项目现有 Unity 版本 | 优先贴合现有项目版本。 |
| 渲染 | URP 2D 或项目现有 2D 渲染管线 | Demo 阶段避免重做渲染管线。 |
| 地图 | Tilemap + 房间预制体 | 快速搭建箱庭地图。 |
| 配置 | ScriptableObject + JSON/CSV 导入 | Demo 先 ScriptableObject，后续接正式表格。 |
| 战斗 | 复用现有角色、怪物、技能系统 | Demo 不重写完整战斗框架。 |
| AI | 简化状态机 + NavMesh/寻路点 | 第一版只做追击、攻击、返回、死亡。 |
| UI | UGUI 或项目现有 UI 框架 | 优先复用现有弹窗、背包、奖励表现。 |
| 存档 | 本地 JSON | 仅保存关卡解锁、Demo 调试数据。 |

### 13.2 架构原则

- 数据驱动：地图元素、掉落、怪物、诅咒、撤离规则全部可配置。
- 局内外分离：局内收益只进入临时容器，撤离成功后再写入正式账户。
- 状态机控制流程：进入、探索、挑战、撤离、死亡、结算状态清晰可追踪。
- MVP 先通闭环：先完成能玩的 1 张地图，再扩展复杂系统。
- 玩法系统解耦：背包、掉落、刷怪、撤离、诅咒不直接互相硬引用，通过事件通信。

## 14. Demo 运行时模块

```text
DungeonRunController
  管理单局生命周期：初始化、开始、暂停、死亡、撤离、结算。

DungeonMapController
  加载地图、房间、资源点、传送门、撤离点。

DungeonTimerService
  记录单局时间，驱动魔物等级提升、狂暴、定时刷怪。

MonsterSpawnSystem
  负责刷怪点、波次、复活、精英/Boss 触发。

MonsterScalingSystem
  根据时间和关卡配置计算怪物倍率。

InteractSystem
  处理宝箱、矿堆、祭坛、传送门、资源点交互。

LootSystem
  根据掉落表生成局内货币、残页、钥匙、宝物碎片、完整宝物。

RunInventorySystem
  管理局内背包、容量、占格、替换、丢弃、结算携带。

CurseChoiceSystem
  管理三选一触发、选项生成、效果应用、收益倍率。

ExtractionSystem
  管理普通撤离、撤离卷轴残页、撤离点挑战、完美撤离。

SettlementSystem
  根据撤离类型计算最终收益，并写入局外账户或 Demo 结果页。

DungeonHUD
  展示时间、魔物等级、残页、背包、收益、诅咒、撤离提示。
```

## 16. 单局状态机

```text
NotStarted
  -> Loading
  -> Exploring
  -> ExtractionPreparing
  -> ExtractionChallenge
  -> Settlement
  -> Finished

Exploring
  -> PlayerDead
  -> NormalExtract
  -> ExtractionPreparing

PlayerDead
  -> Revive
  -> FailedSettlement
  -> SafeDeathSettlement
```

状态说明：

- `Exploring`：正常探索、刷怪、拾取、三选一、背包管理。
- `ExtractionPreparing`：玩家在撤离点范围内停留，准备激活挑战。
- `ExtractionChallenge`：30 秒倒计时，持续刷怪，玩家存活即成功。
- `NormalExtract`：残页足够后主动提前撤离。
- `FailedSettlement`：未满足撤离条件死亡，收益清零。
- `SafeDeathSettlement`：残页足够后死亡，按普通撤离带出。

## 17. 事件流设计

建议核心系统通过事件通信，降低耦合。

| 事件 | 触发方 | 监听方 |
|---|---|---|
| `RunStarted` | DungeonRunController | HUD、Spawn、Timer、Map |
| `MonsterKilled` | 怪物实体 | Loot、Curse、Spawn、Quest |
| `InteractCompleted` | InteractSystem | Loot、Map、HUD |
| `LootPicked` | LootSystem | Inventory、Extraction、HUD |
| `ScrollFragmentChanged` | ExtractionSystem | HUD、Tutorial |
| `MonsterLevelChanged` | MonsterScalingSystem | HUD、Spawn、Monster |
| `CurseChoiceTriggered` | CurseChoiceSystem | UI、Timer |
| `CurseSelected` | UI | Curse、Settlement、Spawn |
| `ExtractionChallengeStarted` | ExtractionSystem | Spawn、HUD、Audio |
| `RunSettled` | SettlementSystem | UI、Account、Analytics |

## 18. 关键验收标准

### 18.1 玩法验收

- 玩家能在 1 分钟内理解目标：搜集资源、凑残页、找撤离点。
- 玩家能在第 1 局内完成一次普通撤离。
- 玩家能明显感知 3 分钟后怪物压力变强。
- 玩家在背包满时会产生至少一次取舍。
- 玩家在三选一时能理解收益提升伴随风险提升。
- 完美撤离挑战有压迫感，但不是纯数值秒杀。

### 18.2 技术验收

- 可通过配置调整残页需求数量、撤离时间、怪物等级提升间隔。
- 可通过配置新增掉落项，不需要改代码。
- 可通过配置调整资源点掉落和刷怪波次。
- 局内收益在撤离成功前不会写入正式背包。
- 失败、普通撤离、完美撤离三种结算结果可稳定复现。
- Demo 至少包含基础 PlayMode 测试或调试面板验证核心流程。

## 19. 开发里程碑

### M1：可跑通单局闭环

- 创建 Demo 场景。
- 玩家出生、移动、战斗接入。
- 地图中放置资源点和刷怪点。
- 支持拾取局内道具。
- 支持普通撤离和失败结算。

### M2：加入风险收益系统

- 加入局内背包容量和替换逻辑。
- 加入撤离卷轴残页。
- 加入掉落表。
- 加入肉鸽三选一。
- 加入收益倍率和结算页。

### M3：加入压力曲线

- 加入魔物等级计时提升。
- 加入狂暴状态。
- 加入精英怪触发。
- 调整怪物刷新频率和数值倍率。

### M4：加入完美撤离挑战

- 加入撤离点激活逻辑。
- 加入 30 秒倒计时挑战。
- 加入挑战期间专用刷怪波次。
- 加入完美撤离奖励和下一关解锁。

### M5：调参与体验优化

- 优化 HUD 提示。
- 优化背包满时的操作。
- 优化撤离残页提示。
- 调整 5 - 8 分钟节奏。
- 加入基础埋点和调试面板。

## 20. 风险与建议

| 风险 | 说明 | 建议 |
|---|---|---|
| 搜索感不足 | 如果资源点太线性，玩家会感觉只是刷图。 | 给支路资源房、高价值宝箱、条件门增加明确收益差异。 |
| 死亡清零挫败过强 | 移动端玩家对长时间失败更敏感。 | 通过残页保底、单局一次复活、普通撤离降低挫败。 |
| 三选一理解成本高 | 诅咒和收益倍率如果表达不清，会影响决策。 | 每个选项固定展示“获得 / 代价 / 收益提升”。 |
| 背包系统工程成本高 | 复杂占格背包会拖慢 Demo。 | 第一版使用格子容量，后续再升级形状占格。 |
| 30 秒挑战变成纯战力门槛 | 如果怪物数值过硬，操作和续航无法体现。 | 用弹幕密度、刷怪位置、精英技能制造压力，而不是只堆数值。 |

## 21. 推荐下一步

建议先产出 Unity Demo 的最小可玩版本：

1. 使用灰盒地图搭一张主线地图。
2. 接入已有玩家战斗与怪物模板。
3. 实现资源点、残页、背包、撤离结算。
4. 用配置表驱动第一批掉落和怪物波次。
5. 跑 10 局测试单局时长、死亡率、普通撤离率、完美撤离率。

第一版核心目标不是内容量，而是证明“玩家愿意多搜一点，但又担心死掉亏损”的决策张力成立。
