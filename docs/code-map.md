## 4. 核心模块定位

### 4.1 局内主循环

文件：

```text
js/raid.js
```

关键职责：

- 创建 raid。
- 构建玩家。
- 生成敌人。
- 处理输入。
- 更新玩家、敌人、子弹、掉落。
- 检查死亡和撤离。
- 渲染 HUD。
- 产出结算结果。

关键位置：

| 逻辑 | 位置 |
|---|---|
| 构造函数初始化 | `Raid(loc, carried)` |
| 生成敌人 | `_spawnEnemies()` |
| 每帧更新 | `update(dt, w, h)` |
| 搜索交互 | `_handleInput(dt)` 中搜索段 |
| 搜索完成收集 | `_collect(cont)` |
| 找最近容器 | `_nearestContainer()` |
| 撤离检测 | `_checkExtract(dt)` |
| 敌人死亡回调 | `onEnemyKilled(e)` |
| 结算 | `_finish(outcome)` |
| HUD 绘制 | `_drawHUD(ctx, w, h)` |

后续改造：

- 在 `Raid` 增加残页、魔物等级、诅咒、收益倍率等局内状态。
- 在 `update` 中驱动魔物等级和狂暴。
- 在 `_finish` 中新增失败撤离、普通撤离、完美撤离。
- 在 `_drawHUD` 中显示残页、魔物等级、狂暴、收益倍率。

## 7. Phase 0 结论

该项目适合作为关卡内 Demo 底座。原因：

- 已经有完整的搜索、战斗、撤离、死亡损失闭环。
- 局内核心逻辑集中在 `raid.js`、`world.js`、`entities.js`、`data.js`。
- 自动测试覆盖较完整，改造后可以继续用 smoke 测试兜底。
- 无引擎依赖，环境成本低。

主要改造风险：

- 现有项目包含较多局外经济、仓库、商店、任务线，Demo 阶段应主动砍掉或绕过。
- 背包当前按堆叠项数量计算，不是按占格成本，需要改。
- 地图当前偏程序化生成，不是固定箱庭路线；如果要强验证路线节奏，需要锁种子或改固定布局。
