# ProjectSDC 五关挑战与局外资产循环开发计划

## 1. 文档目的

本文档用于指导 ProjectSDC 从单局 Demo 进入五关挑战、遗物货币、商店配装和跨关卡资产继承阶段。

Phase 37 已完成，Phase 38 尚未启动。后续版本在保留现有局内战斗闭环和五关入口的基础上，正式接入遗物永久货币、结算明细和轻量局外资产循环；暂不开发装备升级、角色成长等长期养成模块。

## 3. 已确认规则

### 3.1 完美撤离

1. 玩家进入绿色撤离圈并静止 2 秒，激活完美撤离阶段。
2. 激活后开始 30 秒生存倒计时。
3. 激活后玩家可以离开绿色撤离圈。
4. 激活后挑战不可取消，玩家不需要返回绿色撤离圈。
5. 玩家在限定时间结束时存活，则判定完美撤离。

### 3.2 其他玩法规则

- 普通传送门：玩家碰到后立即切换房间。
- 条件传送门：玩家在传送门旁静止并交付资源，满足条件后立即切换房间。
- 金币是局内专属货币，不进入背包格子。
- 自动瞄准优先选择最近敌人。
- 技能升级使用三选一。
- 技能和诅咒共享同一个选择池。
- 每次三选一至少出现一个诅咒选项。
- 只在玩家头顶显示血条，不给怪物增加头顶血条。

### 3.3 五关、结算与解锁

- 可挑战关卡扩展为 5 关，初始只开放第 1 关。
- 普通撤离保留本局资产，但不解锁下一关。
- 完美撤离视为通关，保留本局资产并解锁下一关。
- 失败、死亡或放弃时，本局带入和局内获得的武器、护甲及道具全部消失。
- 已解锁关卡允许重复挑战。
- 关卡房间数逐关递增到 8 个；该数量只统计常规挑战房，不包含出生房、奖励房和撤离房。
- 现有挑战包继续在地图生成时随机抽取，玩家不选择挑战包；后续随关卡一起扩展挑战包池。

### 3.4 遗物、货币与商店

- 玩家成功撤离时，`valuable` 类型遗物折算为可累计的局外货币，不进入局外仓库。
- 局内金币和撤离残页不进入局外经济。
- 武器、护甲和允许携带的道具在成功撤离后进入仓库，可带入后续关卡。
- 商店使用遗物折算货币购买武器、护甲和道具，商品随关卡进度逐步解锁。
- 手枪无需购买；玩家破产且没有可用武器时，进入关卡默认携带应急手枪。
- 应急手枪属于防卡死装备，不作为可出售、可重复入库的经济产出。

### 3.5 后续开发边界

- 每轮试玩按 10 局执行。
- 普通撤离时长以 3-5 分钟为复盘参考，不作为强制限时。
- 完美撤离时长以 5-8 分钟为复盘参考，不作为强制限时。
- 最终验收同时覆盖桌面键鼠和移动触控。
- 本阶段只接入五关、遗物货币、商店、仓库和配装闭环；不开发装备强化、角色等级、技能树或付费系统。

## 5. 阶段计划

### 5.1 Phase 25-26：现有改动收口

目标：完成已经实现的试玩节奏和结算数据能力，不扩大功能范围。

工作内容：

1. 检查 Phase 25/26 当前代码差异，确认没有混入其他改动。
2. 人工检查中英文结算页的节奏标签和试玩指标。
3. 检查调试面板在常见桌面和移动尺寸下不遮挡关键 HUD。
4. 运行完整 smoke 验证。
5. 更新完成记录，提交并推送远程仓库。

验收标准：

- 结算页正确显示偏快、目标区间、偏慢三种节奏结果。
- 结算页正确显示房间、搜索、金币和三选一指标。
- Demo 以外的 raid 不显示 Demo 试玩指标。
- 自动验证保持全通过。
- 工作区改动已提交并推送。

### 5.2 Phase 27：试玩基线与问题归因

目标：在不改数值的前提下完成第一轮 10 局脚本化路线基线验证，建立调参基线。

每局记录：

| 字段 | 说明 |
| --- | --- |
| 输入方式 | 脚本路线控制器 |
| 地图方向 | 横向或竖向 |
| 结算类型 | 失败、普通撤离或完美撤离 |
| 单局时长 | 结算时显示的局内时间 |
| 探索房间 | 总房间数和奖励房间数 |
| 资源搜索 | 已完成搜索的资源点数量 |
| 金币行为 | 获得、花费、开启金币门数量 |
| 构筑行为 | 三选一总数、技能数、诅咒数 |
| 背包状态 | 是否装满、是否发生主动取舍 |
| 失败原因 | 死亡、操作误解、提示不清或流程异常 |
| 主观问题 | 压力过高、节奏拖沓、目标不清等 |

执行规则：

1. 第一轮脚本基线期间不改参数。
2. 试玩结束后统一分类为阻塞问题、规则问题、数值问题、反馈问题和兼容问题。
3. 先修阻塞问题，再进入 Phase 28 调参。

验收标准：

- 完成 10 局脚本化有效记录。
- 失败、普通撤离和完美撤离路径至少都被脚本验证一次。
- 横向和竖向地图都被覆盖。
- 资源搜索、金币门、诅咒和技能构筑均被覆盖。
- 真实桌面键鼠和移动触控留待 Phase 30 回归。
- 形成按优先级排序的问题清单。

### 5.3 Phase 28：节奏与难度调参

目标：使用 Phase 27 数据调整现有配置，使核心路线进入目标时长区间。

允许调整：

- 主线房间数量和奖励房生成概率。
- 房间波次数量、单波怪物数量、预警和复活间隔。
- 怪物生命、伤害、移动速度和弹道速度。
- 资源点数量、搜索时间和掉落权重。
- 残页产出和普通撤离达成速度。
- 金币产出、金币门费用和支付速度。
- 技能/诅咒触发时间与击杀阈值。
- 完美撤离阶段的刷怪间隔和压力强度。

限制：

- 原则上只调整配置和现有规则参数。
- 不新增玩法系统、道具类别、敌人机制或房间类型。
- 若数据暴露结构性问题，必须先补充计划并由用户确认。

验收标准：

- 再执行一轮 10 局试玩。
- 普通撤离主要落在 3-5 分钟参考区间，但超出区间不强制结算。
- 完美撤离主要落在 5-8 分钟参考区间，但超出区间不强制结算。
- 金币门不存在因前序金币不足导致的必然死路。
- 第一战斗房不会出现无预警秒杀或明显无解压力。
- 背包、残页、血量和收益之间能形成至少一次实际取舍。

### 5.4 Phase 29：信息反馈与可读性打磨

目标：只修复试玩中已经出现的理解和反馈问题，不扩展机制。

候选范围：

- 首分钟目标提示：搜索资源、收集残页、寻找撤离点。
- 房间即将开战、锁门、清房和复活阶段的状态反馈。
- 普通门与金币门的外观和交互状态区分。
- 金币不足、支付中和支付完成的反馈。
- 背包已满、溢出落地、附近战利品和拖拽结果反馈。
- 完美撤离 2 秒激活、30 秒存活和挑战完成反馈。
- 玩家头顶血条在不同背景和分辨率下的可读性。

验收标准：

- 新玩家能够在首分钟说清搜索、残页和撤离目标。
- 关键失败可以区分为玩家决策失败，而不是提示缺失。
- 桌面与移动端的文字、按钮、HUD 和背包界面无重叠。
- 横向和竖向地图均无残影、花屏或错误裁切。

### 5.5 Phase 30：兼容回归与演示交付（已完成）

目标：交付可供公司内网试玩和演示的稳定版本。

测试矩阵：

| 维度 | 最低覆盖 |
| --- | --- |
| 桌面浏览器 | Chrome、Edge |
| 桌面输入 | 键盘移动、快捷键、背包拖拽与点击 |
| 移动端 | 至少一台触控设备或移动端浏览器模拟 |
| 地图 | 横向主线、竖向主线、奖励支路 |
| 结算 | 失败、普通撤离、完美撤离 |
| 连续性 | 连续完成 3 局，不刷新页面 |
| 网络场景 | 本机访问、同内网设备访问 |

本轮验收反馈的 HUD 口径：

- Demo 的 3-5 分钟与 5-8 分钟仅为结算复盘参考，不显示局时倒计时，也不触发强制 MIA。
- 顶部中央显示当前魔物等级与距下一等级的倒计时进度条；等级封顶后显示最高威胁。
- 右侧状态区固定显示局内金币；已选诅咒在威胁条下以图标展示，桌面悬停或点击、移动端点击均显示名称、效果和收益提示。
- 搜索不阻断射击，也不因开火中断；移动离开搜索范围仍会中断搜索。
- 背包内的非弹药物品不堆叠，每件物品单独占用其网格尺寸；弹药继续进入备用弹药池。

交付内容：

- 完整 smoke 验证结果。
- 人工试玩验收记录。
- 已知问题清单，阻塞问题必须为零。
- 本地和内网启动说明。
- 阶段完成文档。
- 最终提交并推送远程仓库。

### 5.6 Phase 31：挑战框架与入口（已完成）

目标：建立可复用的挑战定义，让不同挑战可由数据描述并从 Demo 入口启动。

工作内容：

- 定义挑战 ID、名称、说明、推荐时长、地图规则、敌人曲线、局内修正和结算条件字段。
- 提供挑战选择入口，并把选中的挑战上下文传入战局与结算。
- 首批以现有地图和规则交付高压潮汐、精英围猎、资源匮乏撤离三个挑战原型。
- 仅复用既有局内系统，不引入永久解锁、局外货币或服务器服务。

验收标准：

- 挑战定义不依赖 UI 分支，可由数据新增或调整。
- 选择不同挑战后，战局能读取并应用其局内修正。
- 挑战名称、规则说明与结算身份均可本地化显示。
- 每个首批挑战均有至少一条脚本化启动与结算回归。

### 5.7 Phase 32：战斗职责扩充（已完成）

目标：新增可预警、可反制的敌人职责，提升房间战斗的走位与目标优先级。

本期范围：

- 突击职责：复用现有近战魔物，蓄力后直线压近；蓄力期间受击可打断，横向移动可规避冲刺。
- 射手职责：复用现有精英远程魔物，瞄准线预警后向锁定位置开火；瞄准期间受击或失去视线可打断。
- 职责通过生成参数配置，复用原有数值、掉落、房间和结算规则。

验收记录：

- 首战房不生成职责；后续战斗房按配置概率分配突击或射手职责。
- 突击蓄力环、方向扇形与射手瞄准线、锁定圈均已纳入脚本化回归；蓄力和瞄准均可由受击打断，射手失去视线也会取消瞄准。
- 已完成本地试玩页面检查，突击蓄力预警正常显示；完整 smoke 与 Phase 27 基线均通过。

### 5.8 Phase 33：局内构筑扩充（已完成）

目标：扩充技能、诅咒和风险收益选项，形成可辨识的构筑方向。

已确认范围：

- 保持每局两次三选一，不调整触发条件或选择次数。
- 新增 3 个技能，分别强化移动、治疗和搜索。
- 新增 3 个诅咒，分别以更快射击、更高残页掉率和更远射程交换更高战斗压力。
- 仅复用现有属性修正、选择界面、结算收益与本地化链路；不新增玩法机制、敌人、房间或局外内容。

验收记录：

- 新增奔行本能、战地分诊、快速搜寻三个技能，以及超频扳机、残页赌约、远视之债三个诅咒。
- 每局仍保持两次三选一；技能不增加收益倍率，诅咒保持风险与收益倍率联动。
- 已通过完整 smoke、Phase 27 基线和本地三选一页面检查。

### 5.9 Phase 34：挑战关卡包（已完成）

目标：基于挑战框架交付多组可重复游玩的关卡规则组合。

已确认范围：

- 保留并扩展为 6 个挑战包；挑战在房间地图生成时从统一随机池自动抽取，玩家不选择挑战包。
- 挑战、掉落、诅咒和技能统一登记到随机池；各系统继续按自身的既有规则从对应子池抽取，避免为每个挑战拆分独立脚本。
- 新增挑战通过地图规则、已有局内修正和突击/射手职责生成概率组合实现；不新增敌人类型、房间类型、掉落类型或局外内容。
- 挑战入口直接启动随机挑战；暂停页和结算页继续显示本局实际抽中的挑战身份。

验收记录：

- 高压潮汐、精英围猎、资源匮乏撤离、突围封锁、瞄准火线、豪赌路线共 6 个挑战包已登记到统一挑战池。
- 主界面不再提供挑战包选择；地图生成前自动从池中抽取，暂停页和结算页显示本局身份。
- 已通过完整 smoke、Phase 27 基线和本地随机入口页面检查。

### 5.10 Phase 35：挑战迭代与平衡（已完成）

目标：以脚本基线和人工多局试玩，持续调整挑战胜率、时长、构筑选择和死亡来源。

本轮范围：

- 以统一脚本路线执行 10 局挑战基线，覆盖 6 个挑战包、横竖地图、三种结算、金币支路及技能/诅咒选择。
- 输出挑战身份、时长、结算、探索、金币和构筑指标，作为后续人工试玩与数值调整的共同基准。
- 首轮只建立数据基线，不因脚本强制结算结果直接调整数值；真实死亡来源、胜率和主观压力由后续人工试玩补充。

首轮基线：

- `--phase35-baseline` 已完成 10 局，覆盖全部 6 个挑战包；结算分布为失败 3 局、普通撤离 5 局、完美撤离 2 局，平均脚本时长 401 秒。
- 该分布来自脚本指定的结算路径，只用于验证路线、指标和结算覆盖，不作为真实挑战胜率或平衡结论。
- 本地随机挑战页面已抽检一局高压潮汐，暂停信息显示正常且控制台无错误。

### 5.13 Phase 38：遗物货币结算（未启动）

目标：将成功撤离时携带的遗物折算为永久货币，并给出可复核的结算明细。

工作内容：

- 仅将 `valuable` 类型物品按价值和本局奖励倍率折算为局外货币。
- 武器、护甲、医疗品和其他允许携带的物品不参与遗物折算，进入资产返还流程。
- 普通撤离与完美撤离均可获得遗物货币；失败、死亡和放弃不获得货币。

验收标准：

- 同一局结算不能重复发放货币。
- 局内金币和撤离残页不会进入局外余额。
- 页面刷新后累计货币保持一致；异常存档值会被清洗。

### 5.14 Phase 39：商店、仓库与配装（未启动）

目标：恢复并适配现有局外页面，让永久货币能够购买并配置关卡装备。

工作内容：

- 商店按武器、护甲和道具分类，商品通过关卡解锁组逐步开放。
- 购买时校验关卡进度、余额和商品配置；成功后扣款并入库，失败不改变资产。

### 5.15 Phase 40：跨关卡资产与失败损失（未启动）

目标：打通“上一关获得、下一关带入、失败后失去”的风险资产闭环。

工作内容：

- 关卡启动时先从仓库扣除选定武器、护甲和道具，再创建战局携带状态。
- 普通或完美撤离后，存活装备与局内获得的可携带物进入仓库；遗物转为货币。
- 失败、死亡或放弃时不返还带入资产，也不保留局内获得物。
- 上一关获得的武器可在任意已解锁关卡的配装页选择。
- 处理仓库容量、重复物品和应急手枪的边界，禁止通过结算复制物品。

验收标准：

- 覆盖购买 -> 带入 -> 普通撤离 -> 再次带入，以及购买 -> 带入 -> 失败 -> 资产消失两条主链路。
- 结算、刷新和重复点击不会重复返还装备。
- 应急手枪不会出售、永久入库或成为货币来源。

## 7. 执行顺序与变更规则

1. Phase 36 已完成五关数据、存档迁移和常规挑战房预算。
2. Phase 37 已完成五关入口、锁定状态和顺序解锁展示。
3. Phase 38-40 依次完成遗物货币、商店配装和跨关卡资产风险闭环。
4. Phase 41 扩展五关内容与挑战包，Phase 42 完成全流程回归。
5. 每个阶段结束后运行完整 smoke；涉及五关内容时补充对应脚本基线。

开发过程中如出现以下情况，必须暂停并重新确认：

- 需要改变已确认的撤离、传送门、金币、自动瞄准或三选一规则。
- 需要改变普通撤离保资产但不解锁、完美撤离解锁下一关的规则。
- 需要让应急手枪进入仓库、出售或参与遗物货币循环。
- 需要把出生房、奖励房或撤离房计入 4-8 个常规挑战房数量。
- 时长参考区间与实际玩法冲突，需要重新定义 3-5 分钟或 5-8 分钟参考范围。
- 移动端与桌面端需要采用不同玩法规则，而不仅是输入和布局差异。
